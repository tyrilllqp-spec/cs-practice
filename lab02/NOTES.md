# Заметки по Git

## Локальные состояния Git

**Рабочая папка (working directory)** — это обычная папка на компьютере, в которой лежат файлы проекта. Здесь мы создаём, редактируем и удаляем файлы. Git видит все изменения в этой папке, но пока не сохраняет их автоматически.

**Индекс (staging area)** — это промежуточная область между рабочей папкой и историей коммитов. Когда мы выполняем `git add`, изменённые файлы попадают в индекс. Индекс позволяет выбрать, какие именно изменения войдут в следующий коммит, а какие пока останутся только в рабочей папке.

**Коммит (commit)** — это зафиксированный снимок состояния проекта, сохранённый в истории Git. Каждый коммит содержит хеш, автора, дату и сообщение. Коммиты образуют цепочку, по которой можно вернуться к любому предыдущему состоянию проекта.

## Различие Git и GitHub

**Git** — это локальная система контроля версий, программа, которая устанавливается на компьютер и работает с историей изменений файлов. Git хранит все коммиты, ветки и историю прямо на вашем диске в папке `.git`. Интернет для работы Git не нужен.

**GitHub** — это облачный сервис для хранения Git-репозиториев на удалённом сервере. GitHub позволяет делиться кодом с другими разработчиками, совместно работать над проектами, делать pull request и code review. GitHub — это один из многих сервисов (есть ещё GitLab, Bitbucket), а Git — это сам инструмент.

Если провести аналогию: Git — это двигатель, а GitHub — это гараж в облаке, где вы храните копию машины и показываете её другим.

### Что сравнивают git diff и git diff --staged

- `git diff` (без флагов) сравнивает **рабочую папку** с **индексом**. Показывает изменения, которые ещё не добавлены через `git add`.
- `git diff --staged` сравнивает **индекс** с **последним коммитом**. Показывает изменения, которые уже добавлены в индекс и войдут в следующий коммит.
